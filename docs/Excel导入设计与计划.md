# Excel 导入功能 · 设计与实施计划

> 制定日期：2026-07-31
> 背景：用户目前普遍用手搓 Excel 维护人脉，需要一条「Excel → 关系图谱」的顺畅导入路径。
> 依据：需求文档 v1.2 第三章「方式五：批量导入」、交接文档 5.6 ImportTask 设计。

## 一、总体流程（对齐交接文档 5.6 的 8 步流程）

```
选择文件(xlsx/csv)
→ ① 前端 SheetJS 解析表头 + 全量行
→ ② 自动猜测字段映射（表头词典：如"手机/联系电话/电话号码"→ phone）
→ ③ 用户确认/调整映射（未识别列可选：映射到字段 / 并入备注 / 忽略）
→ ④ 前端归一化清洗（见下）→ 生成标准行
→ ⑤ POST /api/import/preview：服务端校验 + 查重（库内 + 批内）
→ ⑥ 预览页展示：有效/无效/重复行，用户勾选重复行的处理方式
→ ⑦ POST /api/import/persons：事务内批量写入，逐行容错
→ ⑧ 返回导入报告（成功/跳过/失败明细）
```

**架构分工**：
- 前端负责解析与映射（浏览器内完成，文件不出端，手机也可用）
- 服务端负责校验、查重、批量写入（保证数据一致性与鉴权）

## 三、内置清洗规则（MVP 已实现）

| 规则 | 说明 |
|---|---|
| 去空白 | 所有单元格 trim；空字符串 → null |
| 电话归一化 | 去除空格/横线/+86 前缀 |
| 关系强度中文映射 | 强/很熟/铁 → strong；中/一般/还行 → medium；弱/不熟/泛泛 → weak |
| 敏感级别中文映射 | 高/保密 → high；中 → medium；低/公开/空 → low |
| 状态中文映射 | 待跟进/跟进 → follow-up；活跃/正常 → active；冷却/冷 → cold |
| 标签拆分 | 按 、 ， , / 空格 ; 分号拆为数组并去重 |
| 别名拆分 | 同标签拆分规则 |

## 四、校验与查重规则（服务端）

- **无效行**：姓名为空；枚举值经清洗后仍不合法（直接置默认值并警告，不阻断）
- **重复判定**：
  - `exact`：姓名+电话均相同（与库内或批内）→ 默认跳过
  - `name_only`：仅姓名相同 → 标记提示，由用户决定跳过或照常导入
- **单次上限**：5000 行；写入在单事务内完成，逐行容错（个别失败不影响整批）

## 五、清洗-转换-再导入（后续 P1 增强，本次先规划）

针对 schema 严重不符（如一行多人、合并单元格、多 sheet、字段藏在长文本里）：

1. **映射模板保存**：用户确认过的映射保存为模板（settings 表 key=`import_mapping_templates`），下次同表头自动套用
2. **LLM 辅助映射**：表头 + 前 5 行样例发给服务端 Ollama，返回映射建议与值清洗建议（LLM 只建议，用户确认，不直接写入——保留决策 #2）
3. **错误行导出修复**：预览页支持将「无效/存疑行」导出为 xlsx，用户线下修复后再次导入（形成清洗闭环）
4. **值级转换规则**：用户可对某列指定转换（如"北京市海淀区"→ 取城市；生日列格式统一），规则随模板保存
5. **一行多信息拆解**：备注列中的"老李介绍，聊过融资"类文本走 LLM 抽取，生成互动记录与介绍关系（连接 EntityMention 机制）
6. **ImportTask 落库**：导入历史记录表（import_type/status/result_json/error_summary），支持追溯与重跑
